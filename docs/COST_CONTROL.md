# 大模型成本控制

## 当前策略

1. 高频产品问答使用进程内缓存。
   - 仅缓存通过校验的 `产品文档` 回答。
   - TTL 1 小时，最多 256 条。
   - 带“它、这个、刚才、继续”等上下文指代的问题不缓存。
   - 缓存只保存在当前服务进程内，重启即清空。

2. 按场景缩短上下文。
   - 产品文档：明确问题不携带历史；需要指代时最多 2 轮。
   - 设备数据：最多 3 轮。
   - 通用对话：最多 4 轮。
   - 指标解释：最多 1 轮。

3. 降低检索和输出预算。
   - 产品候选切片由 6 个降为 4 个，最终仍按相关性裁剪。
   - 产品文档输出最多 240 tokens。
   - 设备数据输出最多 280 tokens。
   - 通用对话输出最多 320 tokens。

4. 指标定义、报告、趋势分析和安全边界继续使用确定性逻辑，不调用大模型。

## Token 观测

模型返回 usage 时，请求日志会包含：

```text
Tokens:输入token/输出token
```

未返回 usage 的兼容接口记录为 `Tokens:0/0`，不会影响回答。

## 注意

- 患者个人数据、报告和趋势结果不能跨用户缓存。
- 产品文档更新后应重启服务，避免旧缓存继续返回 1 小时。
- 如果缓存命中仍需要记录埋点，应在网关层用新的 `request_id` 记录 `CACHE_HIT`。
